# MCP 多实例（一个端口、一份客户端配置）

## 问题

DEV Framework 的 MCP 服务器跑在**编辑器进程内**。同时打开多个装了这个框架的 Godot 编辑器时，
旧实现是「每个编辑器各绑一个端口」：

- 端口只有一个能绑上，其余实例的 MCP 服务器直接起不来（日志里一条 `监听端口 8932 失败`）；
- 想绕开就改端口，但那意味着**每个项目一份端口 + 每个端口一条客户端 MCP 配置**，改一次要动
  一堆地方，而且很容易连到错的那个项目上（新闻里最常见的翻车：改完代码没反应，因为在改另一个
  窗口的场景）。

## 方案：首个抢到端口者当"中枢"，其余自动登记

```
┌─────────────┐   GET/POST /mcp (固定端口, 唯一对客户端可见)   ┌──────────────────────────┐
│ AI 客户端    │ ────────────────────────────────────────────▶ │ 实例 A（中枢 hub）        │
│ (一条配置)   │ ◀──────────────────────────────────────────── │  127.0.0.1:8932          │
└─────────────┘                                               │  · 自己的全量工具         │
                                                              │  · 实例注册表 + 路由      │
                                                              └───────┬──────────┬───────┘
                                                                      │ 转发      │ 转发
                                                        ┌─────────────▼──┐  ┌────▼───────────┐
                                                        │ 实例 B（成员）  │  │ 实例 C（成员）  │
                                                        │ 127.0.0.1:52600│  │ 127.0.0.1:...  │
                                                        │ 临时端口        │  │ 临时端口        │
                                                        └────────────────┘  └────────────────┘
```

1. 每个实例启动时先算自己的身份（`项目名@项目路径哈希`）。
2. 尝试绑**机器级固定端口** `dev_framework/mcp/hub_port`（默认 8931，本项目设 8932）。
   绑上 = 本实例就是中枢。
3. 绑不上 = 本机已有中枢。退让到 `listen(0)`，由**系统分配**一个临时端口（内核保证唯一，
   比「端口+1」这类自己算的备用端口可靠），然后每 4 秒向中枢登记一次。
4. 客户端**只需要连中枢那一个地址**。工具表就是中枢自己的全量工具，每个工具多一个可选
   `instance` 参数；带上它就转发到目标实例，省略就用 `use_instance` 设的默认目标，
   再省略就作用于中枢自己。

对 AI 来说只是多了两个工具：`list_instances`（看有哪几个编辑器）与 `use_instance`（选一个）。

### 为什么不是"工具名加实例前缀"

那样工具数 × 实例数，几十个工具乘以几台编辑器，工具表直接撑爆上下文；而且每个工具的说明、
annotations 全要复制一份，必然漂移。转发方案里工具表不变，schema 只多一个参数。

### 为什么不做独立 hub 进程

中枢本身就是一个编辑器实例，天然拥有完整工具实现，**零外部依赖**（不需要 node / python /
单独编译的二进制）。代价是中枢随那个编辑器退出 —— 由下面的接管机制补偿。

### 中枢退出怎么办

成员的心跳连续失败 3 次（约 12 秒）后尝试抢绑中枢端口：

- 抢到 → 自己升格为中枢，其余成员下个心跳周期自动登记到它；
- 抢不到 → 说明有别的实例先接管了（端口互斥由内核保证，不会出现两个中枢），继续按成员运行。

正常关闭编辑器时会主动发一次注销请求（不等响应），所以常见情况不会等满 12 秒。

### 为什么不用注册表文件 + pid 判断

能绑上端口本身就是一次**原子的、内核保证的**互斥判定；文件方案要靠轮询、陈旧清理、原子写，
崩溃残留会让"谁是中枢"变成需要容错的状态。Windows 上 pid 还会被复用，用 pid 判断存活的方向
恰恰是错的（把死实例当成活的）。所以这里只有内存注册表 + 心跳，没有落盘状态。

## 配置项

| 设置 | 默认 | 说明 |
|---|---|---|
| `dev_framework/mcp/hub` | `true` | 多实例中枢总开关。关掉回到旧行为（抢不到 `mcp/port` 的实例不启动服务器） |
| `dev_framework/mcp/hub_port` | `8931` | **机器级**中枢端口。所有项目应当一致；本项目显式设为 8932 |
| `dev_framework/mcp/port` | `8931` | 旧行为用的项目级端口，仅 `hub=false` 时生效 |
| `dev_framework/mcp/token` | `""` | 非空时客户端与实例间转发都要带同一个 Bearer token（多实例下必须各实例一致） |

> `hub_port` 是"一个端点"能成立的前提：它是唯一一个**不能按项目各配一个**的端口。
> 换它等于让每个开发者改一次客户端配置，所以默认值与插件历史上的 `mcp/port` 默认值保持一致。

## 用法

客户端配置完全不变，仍然是那个 URL：

```json
{
  "mcpServers": {
    "godot-dev-mcp": { "url": "http://127.0.0.1:8932/mcp" }
  }
}
```

第一次同时开两个项目时，AI 会看到：

```
list_instances →
  role: hub, instance_count: 2
  - DEVFramework@e7735a7f  端口 8932  D:/Work/GodotProject/DEV Framework  ← 本进程 [中枢]
  - PCG@a1b2c3d4           端口 52600 D:/Work/GodotProject/PCG

use_instance({ instance: "PCG@a1b2c3d4" }) →
  active_instance: PCG@a1b2c3d4 —— 之后的工具调用会转发到它
```

之后所有工具调用（`get_scene_tree` / `eval_code` / `game_control` …）都落到那个 PCG 编辑器上。
要切回来：`use_instance({ instance: "" })`。

### `instance` 参数能填什么

| 形式 | 例子 | 说明 |
|---|---|---|
| `uid` | `PCG@a1b2c3d4#42424` | **唯一**。同一项目打开两次时用它精确指定某一个进程 |
| `instance_id` | `PCG@a1b2c3d4` | 项目级身份。**同项目多开时会有歧义**，此时会明确报歧义而不是猜一个 |
| 唯一前缀 | `a1b2` / `PCG` | hash 或项目名前缀，必须唯一命中 |
| 端口号 | `52600` | 手工记过端口时可用 |

`use_instance` 的默认目标按 **uid** 记：用 `instance_id` 做键会让"选中 A 窗口"在同项目的 B 窗口
也生效，而两边 id 完全相同，从错误信息里根本看不出问题。

## 边界与坑

- **不做"唯一的其他实例自动选中"**：开了两个项目、只想改当前这个时，自动选中会静默改错项目。
  报错并要求显式选择只多一次调用。这一点与 MCP for Unity 的取舍一致。
- **成员进程自己也是 MCP 服务器**：临时端口上跑着同一套工具与协议。直接连它也能用（等价于旧行为），
  只是客户端配置里不该写它 —— 那个端口每次启动都会变。
- **`/hub/*` 是实例间内部端点**，不属于 MCP 协议；客户端不需要知道它们。非中枢实例收到这类请求会
  回 404 并说明原因（便于诊断"客户端把端口配到了成员上"）。
- **跨项目 Token 必须一致**：中枢转发时会带上自己的 token；目标实例若配了不同的 token 会回 401，
  表现为一次可见的转发失败而不是静默串味。
- **`get_project_info` 会报身份**：`instance_id` / `instance_role`（hub/member）/ `mcp_port`
  （实际监听端口，成员是临时端口）/ `instance_note`。排查"我到底在操作哪个编辑器"时先看它。
- 导出运行时（`runtime_enabled`）不参与多实例：一个导出包进程只有一个 MCP 端点，注入 `instance`
  参数对它没有意义，故 tools/list 里不会出现该参数。

## 实现位置

| 文件 | 职责 |
|---|---|
| `MCP/MCPInstanceHub.gd` | 身份、注册表、解析/路由、HTTP 转发、`/hub/*` 端点 |
| `MCP/MCPDevServer.gd` | 绑定中枢端口/退让、心跳与接管、tools/list 整形、tools/call 路由、两个实例管理工具 |

`MCPInstanceHub.gd` 不引用任何编辑器类、也不含工具实现，只回普通字典；协议形状全部留在
`MCPDevServer` 里。这样改路由规则不必碰 2000 行的服务器，也不会影响导出包解析图。
