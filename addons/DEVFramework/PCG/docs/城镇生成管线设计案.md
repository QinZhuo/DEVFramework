# 城镇生成管线设计案（CityDef 升级）

> 状态：M1 骨架 + M2 建筑放置 已实施；M3 室内家具待做
> 目标：在现有 PCG 框架（Def → Entity → Tool）内，把 `CityDef` 从「均匀网格填色器」升级为
> 可生成**完善合理的小城镇**的完整管线：周边环境衔接、贴地形道路网、临街房屋分布、
> 户型布局、家具物品摆放，全程 seed 可复现。
>
> M2 实施记录：POI(weight=数量期望)优先挑主街临街大地块 → 住宅按 house_fill_ratio 填充；
> 建筑用锚点定位（门格必须压真实临街格，从门格反推位置），三种子实测门临路率 100%；
> 户型模板库 House_Tiny/Small/Mid + Shop_Large(.tres)，门字符 G 画在最底边，旋转后自动朝街。

---

## 0. 结论先行

1. **不新增 TownDef。** TownDef 与 CityDef 是同一概念——`CityDef` 原地升级为城镇生成
   总控 Def，旧的均匀网格填色模式**直接删除**（不做兼容保留）。
2. 管线拆成 **6 个阶段算法**，实现全部放 `PCGTool` 静态函数（沿用现有代码组织：
   所有算法都在 PCGTool，Def 只存参数）；最终结果写入 `ctx.output` 多个 key +
   一个富实体 `TownLayout`。
3. 一切内容资源走配置：房屋户型 = `TemplateDef` 库、POI 表/家具表 = `ContentEntryDef`
   加权表、装饰散布 = 复用 `PlacementDef`。**不在代码里 new 内容。**
4. 最小基础设施改动：`TemplateDef.stamp` 支持 4 方向旋转（门朝街必需）。

## 1. 目标与非目标

**目标**（输入一张已生成地形 HeightMap/地形格 + 海平面，输出一座小城镇）

1. 选址符合地形逻辑（平缓、近水但不被淹、陆地连通）
2. 道路有层级（主街/次街/巷道）、贴地形绕开陡坡与水面、与城外连通
3. 街区由道路自然围合；地块细分且必须临街；建筑沿街布置、门朝街道
4. 必有 POI（教堂/酒馆/铁匠铺/市场）优先分配到好位置，住宅填充其余
5. 建筑内部按户型模板划分房间，家具按槽位摆放且有语义约束
6. 同 seed 完全复现；存档沿用 seed + 增量约定

**非目标（本期不做）**

- 大城市级路网（张量场/GAN）、多层立交
- 建筑 3D 立面语法（CGA facade）、程序化屋顶
- NPC 日程/经济模拟驱动的城镇演化
- 渲染消费（TileMap/Mesh 实例化仍由项目侧负责，遵守现有「数据生成器」边界）

## 2. 业内方案对比与选型

### 2.1 选址

| 方案 | 来源 | 评价 |
|---|---|---|
| 地形分析评分选址 | Mizdal & Pozzer 2018 (SBGames) | ✅ 选定：平坦度+近水+连通性打分，参数少可控 |
| 随机撒点后验证 | — | 成功率低，仅作回退 |
| 史学/地理模拟聚落演化 | 学术界 | 过重，不做 |

### 2.2 道路网

| 方案 | 来源 | 评价 |
|---|---|---|
| 均匀网格（原 CityDef） | — | 死板，只适合现代规划城市，已删除 |
| L 型走廊 MST（现有 RoadDef） | — | 有骨架但不贴地形、无层级 |
| L-System / 递归细分 | Parish & Müller 2001 经典 | 大城市好用，小城镇易碎 |
| 张量场路网 | Chen et al. 2008 | 最自然但实现复杂，本期不做 |
| **扰动生长 + 递归细分 + 坡度 A*** | SBGames2018 / gamedev SE 公认流程 | ✅ 选定：主街对外 A* 连接，城内从主街扰动生长分支到巷道 |

坡度代价公式（业内常用）：`cost = base * (1 + k * slope^p)`；
水面格高代价（允许则标桥 `bridge_value`，不允许则禁入）；已有道路低代价（借道合并）。

### 2.3 街区提取 + 地块细分

| 方案 | 来源 | 评价 |
|---|---|---|
| OBB Parcelling 定向包围盒递归切片 | Vanegas 2012 / Martin Evans 系列 | 质量最高，需 OBB 拟合与多边形切割 |
| Straight Skeleton 细分 | 同上 | 适合蜿蜒街区，O(N³logN) 复杂 |
| **方向对齐切片（栅格版简化 OBB）** | OBB 的栅格简化 | ✅ 首版选定：交替短轴切片；规则 = 最小面积 / 最大长宽比 / **必须临街并记录临街方向** |

二期可平滑升级为真 OBB（对消费方接口不变，仍输出 parcel 列表）。

### 2.4 建筑放置

| 方案 | 来源 | 评价 |
|---|---|---|
| 必有 POI 先分配 + 其余地块随机填 | gamedev SE (Philipp) 公认做法 | ✅ 选定：先保证「每镇必有」的建筑，再填住宅 |
| 建筑形状语法生成 footprint | CGA/Wonka 2003 | 强但重；首版用模板库替代 |
| 手作房屋模板库（TemplateDef） | 框架已有能力 | ✅ 与 AGENTS.md「内容包装成场景/配置资源」一致 |

门朝向：复用 TemplateDef 的 `G` 字符语义，新增 stamp 旋转使门格对齐地块临街方向。
建筑风格（材质/层数变体）由 `ContentEntryDef` 加权表驱动，同街区倾向同风格（邻接一致性）。

### 2.5 室内布局

| 方案 | 来源 | 评价 |
|---|---|---|
| CGA split grammar 划分房间 | Müller 2006 | 强但配置成本高 |
| 房间邻接图 + BSP 切分 | 学术/roguelike | 中等，户型不够「像家」 |
| WFC 室内瓦片集 | 社区常见 | 可行，框架 WFC 固定格可约束门口，作为二期备选 |
| **手作户型模板库 × 尺寸档位** | 生产游戏最常用（Sims/Caves of Qud 均为 prefab+变体思路） | ✅ 选定：按建筑类型×footprint 尺寸选户型模板，门必须对齐建筑门格 |

户型模板仍是 `TemplateDef`，字符语义扩展为「结构字符 + 家具槽位字符」两级映射。

### 2.6 物品摆放（家具）

| 方案 | 来源 | 评价 |
|---|---|---|
| Sims 式对象骨架约束 | Sims 系列 GDC | 最强语义但工程量大 |
| 纯 WFC 摆家具 | 社区实验 | 约束表达别扭 |
| **槽位摆放 + 加权变体 + 校验修复** | 生产主流折中 | ✅ 选定：户型模板定义固定槽位（床/桌/炉灶），具体物品从加权表抽变体；再泊松散布装饰物填充剩余空地；最后跑校验（门口净空 / 通道可达 / 不重叠）自动修复 |

校验修复是业内标配「post-placement repair for navigation」。

## 3. 总体管线流程

```
输入: heightmap(或地形格) + 海平面 + 可选群系图        ← 已有能力(Pipeline_World 同款)
  │
  ├─ S1 选址      _town_site          → site 点 + 评分
  ├─ S2 道路网    _town_roads         → RoadGraph(节点/边/宽度等级) + 道路格层
  │     主街: site ↔ 城外枢纽(地图边缘) 坡度A*
  │     次街: 沿主街扰动生长; 巷道: 过大区块递归分割
  ├─ S3 街区提取  components() 复用   → 道路围合区块(过滤碎块→广场/绿地)
  ├─ S4 地块细分  _town_parcels       → Parcel{格集, 临街方向}
  ├─ S5 建筑放置  _town_buildings     → Building{footprint, 门, 类型, 旋转} + 印墙层
  │     POI 表优先分配 → 住宅填充 → 广场标记
  └─ S6 室内+家具 _town_interiors     → 每栋建筑: 户型格 + FurnitureSlot[] + 校验修复
  │
输出 ctx.output:
  "town_layout"  : TownLayout (富实体总结果)
  "town_roads"   : GeneratedGrid (道路层: 空/主街/次街/巷道/桥)
  "town_site"    : Vector2i
```

三层栅格（道路/建筑/地面装饰）分开输出，避免现有 `stamp_path` 单格覆盖互踩的问题
（顺带修掉「路压河无桥」「路压田」缺陷——由阶段顺序与分层天然解决）。

## 4. 各阶段详细设计

### S1 选址 `_town_site`

- 输入：HeightMap（或地形格+海平面）、可选 BiomeMap、参数（候选数 N、评分半径 R、
  近水距离带 [d_min,d_max]、最小陆地面积、群系适宜权重表）
- 流程：最大陆地连通域内泊松撒 N 个候选 → 逐个打分：
  - 平坦度：R 内坡度均值/方差（越平越高）
  - 近水：到水面最短距离落在 [d_min,d_max] 得满分（太近被淹、太远缺水）
  - 陆地连续性：R 内陆地占比
  - 群系权重：查表（草原 1.0 / 森林 0.8 / 沙漠 0.3 …）
- 输出：`site: Vector2i` + `score`；全不达标时回退取最高分并 push_warning

### S2 道路网 `_town_roads`

- 主街：site → 地图边缘外枢纽（方向由 seed 决定或外部传入），坡度 A*，宽 2~3 格，
  允许跨水时把水格标 `bridge_value`
- 次街：沿主街每隔 `[street_spacing_min,max]` 扰动出生长点，垂直主街方向贪心扩展 +
  随机弯折（坡度代价同 A*），长到边界/主街/其他路为止，宽 1~2
- 巷道：递归细分剩余空隙直到达到 `alley_target_density`，宽 1
- 数据结构 RoadGraph：`nodes: PackedVector2Array` + `edges: [{a,b,width,class}]`
  （class = MAIN/SECONDARY/ALLEY），同时印出道路格层
- 复杂度控制：A* 用二叉堆（吸取现有 `_connect_region` 线性扫描 O(n²) 的教训）
- 兼容：RoadDef 保留旧 L 型模式，新增 `mode = TERRAIN_GROWTH`；CityDef 内部走新算法

### S3 街区提取

- 对「非道路格」做 flood fill——直接复用 `GeneratedGrid.components()`，零新增
- 面积 < `min_block_area` 的碎块：并入相邻大块 or 标记为绿地；site 附近最大空隙标广场

### S4 地块细分 `_town_parcels`

- 每区块：主方向 = 区块内最长道路段方向（量化 4 向）→ 交替短轴切片
- 切片规则（带概率违反，业内 OBB parcelling 同款）：
  - 硬规则：lot 面积 ≥ `lot_min_area`；长宽比 ≤ `lot_max_aspect`×2
  - 软规则（25% 概率可违）：临街边长 ≥ `frontage_min`
- 无临街边的 lot → 丢弃转绿地/院子（保证每栋建筑都朝街开门）
- 输出 `Parcel {cells, frontage_dir}` 数组

### S5 建筑放置 `_town_buildings`

1. 广场优先：广场周边地块保留
2. POI 分配：`poi_table: Array[ContentEntryDef]`（教堂/酒馆/铁匠/市场…，weight=数量期望，
   位置偏好字段 near_plaza / main_street_frontage）→ 对每个 POI 给所有空地块评分选最优
3. 住宅填充：其余地块按 `house_fill_ratio` 抽签，抽中的按尺寸过滤户型库加权抽取
4. footprint = lot 内缩 `setback`；门格 = 临街边中点附近首个地板格；
   `TemplateDef.stamp_rotated(grid, pos, rotation)` 把门对齐 frontage_dir（需给 TemplateDef 加旋转）
5. 输出 Building{id,type,footprint_rect,door_cell,facing} 数组 + 印建筑层栅格
   （墙/地板/门分值），风格变体记录到 building.style（同街区倾向一致）

### S6 室内布局 + 家具 `_town_interiors`

1. 户型选择：按 (建筑类型, footprint 尺寸档位 S/M/L) 从 `interior_templates` 选 TemplateDef
2. 户型模板字符两级映射：结构字符（墙/地板/门/房间分隔）+ 家具槽位字符
   （B=床 H=炉灶 T=桌 C=椅 S=货架 …）；门字符必须能对齐建筑实际门格（校验不过则换模板）
3. 家具实例化：每个槽位从对应 `ContentEntryDef` 加权表抽具体物品变体（床→木床/豪华床…）
4. 自由装饰：房间剩余空地用 PlacementDef(POISSON) 散布小物件（木桶/盆栽/杂物），
   自动避开槽位与门前 1 格净空圈
5. 校验修复（post-placement repair）：
   - 门口 1 格净空无家具（有则移除该装饰）
   - BFS：从门出发可达所有关键家具槽位与每个房间（不可达 → 移除阻挡物 / 重选户型重试一次）

## 8. 可复现性与存档

- CityDef.generate 内部每阶段 `PCGTool.derive_seed(base, slot)` 独立 RNG，
  阶段顺序固定 → 同 Def + 同 seed 必复现
- 存档沿用 seed + 玩家增量改动；TownLayout.to_data() 支持整体落盘

## 9. 兼容性与测试计划

- 旧模式直接移除：`PCGTool.generate_city` 删除，`City_Grid.tres`、PCGDemo、两个测试同步迁移
- 新增测试（进 Tests/PCG/）：
  - 确定性：同 seed 复现（roads 层逐格相等）、异 seed 不同
  - 约束：道路层连通（site 到地图边缘可达）；地块必须临街或丢弃；
    无高度图回退可用（平地也能出骨架）
  - 性能：96×96 城镇 < 200ms（GDScript 参考值，超了再议 C++ 迁移项）

## 10. 里程碑拆分（建议实施顺序）

1. **M1 骨架**：S1+S2+S3+S4（选址/贴地道路/街区/地块）+ TownLayout + 三层输出 —— 先看城镇骨架图
2. **M2 建筑**：TemplateDef 旋转 + S5（POI 分配/住宅填充/门朝街印墙）
3. **M3 室内**：S6 户型模板 + 家具槽位 + 校验修复
4. **M4 打磨**：示例资源库（户型/POI/家具 .tres）、demo 渲染、性能优化

## 11. 风险与备选

| 风险 | 缓解 |
|---|---|
| 生长式路网在极端山地失败（无路可达边缘） | 回退直线 L 路 + warning；或放宽坡度代价重试 |
| 户型模板与 footprint 尺寸不匹配率高 | 尺寸档位分 S/M/L + 模板不足时缩 footprint 或留空地 |
| GDScript 性能不够（A*/flood fill 大图） | 已有 C++ 原生库通道(FrameworkNative)，热点函数后续平移 |
| 单 int 栅格表达力不足未来需求 | 已用三层 key 分离 + TownLayout 富实体兜底 |
